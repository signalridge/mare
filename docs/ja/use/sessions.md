# セッション

各セッションは作業ディレクトリごとの追記専用 JSONL ファイルです。各エントリが `id` と親を持つため、巻き戻しや再試行は同じファイル内にブランチを作り、元の履歴を保持します。

## セッションの保存場所

```text
~/.local/state/mare/sessions/<directory-slug>/<timestamp>_<id-suffix>.jsonl
```

状態ディレクトリは `$XDG_STATE_HOME` に従います (`MARE_HOME` が設定されている場合は `$MARE_HOME/state`)。`<directory-slug>` は、作業ディレクトリのパスから Unicode の英数字と `.`、`_` を残し、それ以外を `-` に置き換えて `--` で囲んだものです。セッションファイルは起動時ではなく、最初のメッセージが書き込まれたときに作成されます。セッションファイル `abc.jsonl` の添付ファイルは隣りの `abc.attachments/` (ログから移された画像) に、`/rewind` 用のスナップショットは `abc.jsonl.snapshots/` に置かれます。セッションファイルがない場合、スナップショットは `<state>/snapshots/run-<pid>-<uuid>/` を使い、コンパクション時の画像は `<state>/attachments/<session-id または unsaved>/` へフォールバックします。

ファイル構成の全体は [ファイル](../reference/files.md) を参照してください。

### 耐久性とクラッシュからの復旧

- 追記は行単位で行われます。改行のない末尾の行は書き込みの途中切れ (torn write) です。読み取り側は無視し、次の書き込みで切り捨てられます。
- 意味的な区切り (たとえばメッセージの完成時) で、ファイルは `fsync` でディスクにフラッシュされます。書き込みや同期に失敗したバッチは、元の長さまでロールバックされます。
- 改行で終わっているのに解析できない行は、破損として扱われます。mare はそのようなファイルを書き込み用に開いたり書き換えたりすることはありません。読み取り専用で表示するか、安定したスナップショットからフォークできます。
- 同時にセッションを書き込めるのは 1 つのプロセスだけで、セッションの隣のロックファイルで強制されます。別のプロセスがそのセッションを開いている場合、mare は読み取り専用ビューかフォークを提案します。
- mare はセッションを開くときに `running` マーカーを、正常に終了するときに `closed` マーカーを記録します。最後のマーカーが `running` のセッションは、中断されたものです。`/resume` のピッカーではクラッシュとして表示され、`/continue` で中断されたターンを再開できます。

## 再開と続行

```sh
mare -c                      # most recent session in this directory
mare -c --all                # most recent session in any directory
mare -r                      # open the picker
mare -r 3f9a1c2e             # by id, or an unambiguous id prefix (headless)
mare -r "fix login bug"      # by name, case-insensitive (headless)
mare -r -2                   # the second most recent session here
mare -r ./some/session.jsonl # by file path
```

| オプション | 意味 |
| --- | --- |
| `-c`、`--continue` | このディレクトリで最も新しいセッションを続行します。 |
| `-r`、`--resume [VALUE]` | ID、名前、`-N`、パスで再開します。値がない場合はピッカーを開きます。 |
| `--all` | `-c` または `-r` と併用すると、すべてのディレクトリのセッションを対象にします。 |
| `--fork-session` | `-c` または `-r` と併用すると、コピーで続行し、元のセッションには手を加えません。 |
| `--session-id ID` | 新しいセッションにこの ID を使います。英字、数字、`-`、`_` の 8 から 64 文字。ID がすでに存在すると失敗します。 |
| `--name NAME` | 新規または再開するセッションに名前を付けます。 |
| `--no-session` | セッションを保存しません。ランタイムファイルや実行ごとのスナップショットは書き込まれることがあり、ツールもファイルを書き込めます。セッションは再開できず、`-c` や `-r` との併用はエラーです。 |

対話型 UI では、完全な ID でも `-N` でもファイルパスでもない `-r <text>` は、そのテキストを検索語としてピッカーを開きます。ヘッドレス実行では、複数のセッションに一致する名前やプレフィックスはエラーとなり、候補が一覧表示されます。mare が「最新のもの」を勝手に選ぶことはありません。見つからないセッションはエラー (終了コード 1) になり、黙って新しいセッションが作られることはありません。

別のディレクトリで記録されたセッションを再開する場合、TUI はどのディレクトリを使うか尋ねます。`session` プラグインのオプション `resume_cwd` は、`"ask"` (既定)、`"current"`、`"session"` を受け付けます。

```lua
mare.plugin("session", { resume_cwd = "current" })
```

### スクリプト

`mare session new` は、現在のディレクトリに空のセッションを作成してその ID を出力するため、スクリプトで先にセッションを作り、そこにプロンプトを実行できます。

```sh
id=$(mare session new --name nightly-review)
mare -p --resume "$id" "list the TODO comments in src/"
mare -p --resume "$id" "now rank them by risk"
```

`mare session` には `new`、`list`、`fork`、`archive`、`unarchive`、`delete` サブコマンドがあります ([CLI リファレンス](../reference/cli.md#mare-session) を参照)。ユーザー・プロジェクト設定やプラグインを読み込まない軽量ホストで動作し、`--cwd` と (`new` / `fork` 用の) `--name` を使用します。`--model`、`--trust`、`--permission` などの実行オプションは、後続の `mare -p --resume "$id"` 呼び出しに渡してください。[ヘッドレス](headless.md) を参照してください。

## セッション内の操作

| コマンド | 効果 |
| --- | --- |
| `/new` (`/clear`) | 新しいセッションを開始します。古いセッションはディスクに残ります。 |
| `/resume` (`/sessions`) | ピッカーを開きます。`/resume all` はすべてのディレクトリを一覧表示し、`/resume search <text>` は絞り込み、`/resume <id or name>` は 1 つを読み込みます。ターンの実行中は使えません。 |
| `/name <title>` (`/title`、`/rename`) | セッションに名前を付けます。タイトルを省略すると現在の名前を表示します。 |
| `/fork` | 最新のメッセージから新しいセッションにフォークします。`/fork pick` ではメッセージを選べます。 |
| `/clone` | セッション全体を新しいセッションに複製します。 |
| `/tree` | セッションツリーをたどり、以前の任意の時点から分岐します。 |
| `/label <text>` | ツリー上の現在の位置にラベルを付けます。 |
| `/retry` | 直前の回答を新しいブランチで再生成します。古い回答はそのブランチに残ります。 |
| `/continue` | クラッシュや強制終了の後、中断されたターンを続行します。 |
| `/archive` | セッションをアーカイブ済みにして、新しいセッションを開始します。ファイルは残ります。 |
| `/delete` | 確認の後、このセッションを削除します。 |

ピッカーのキー: `Ctrl+D` 削除、`Ctrl+R` 名前変更、`Ctrl+S` 作成日または更新日で並べ替え、`Ctrl+N` 名前付きのみ、`Ctrl+A` アーカイブ済みを表示、`Ctrl+X` アーカイブ、`Ctrl+E` 展開、`Ctrl+T` トランスクリプト、`Ctrl+L` レイアウト変更。`session` プラグインのオプション `picker_style` で、`"comfortable"` (既定)、`"dense"`、`"cards"` を選べます。

### 取り消しと巻き戻し

`/undo` と `/rewind` は別のものです。

- `/undo` は、会話をあるプロンプトの前まで巻き戻し、そのプロンプトのテキストを入力欄に戻します。ディスク上のファイルはそのままです。`/undo` はピッカーを開き、`/undo 2` はプロンプト 2 つ分戻ります。取り消せるのは、最後のコンパクション以降のプロンプトだけです。空でアイドル状態の入力欄で `Esc` を 2 回押すと、同じピッカーが開きます。取り消されたメッセージは、そのブランチとしてファイルに残ります (`/tree` を参照)。
- `/rewind` はファイルを復元します。mare は、どのツールであっても、ファイルを書き込み、削除、名前変更する前にその元の内容を保存し、`/rewind [turn]` はそれらのファイルをそのターンの前の状態に戻します。ファイルのみを復元する、ファイルと会話を復元する、そのターン以降の会話を要約する、のいずれかを選べます。

`/rewind` はシェルコマンドによる変更を取り消せず、そのターンにその旨が表示されます。ターンの後に mare の外でファイルが変更された場合は、一覧に表示され、確認した後にのみ復元されます。バックアップには上限があり (`changes` プラグインのオプション `cap_bytes`、既定は 64 MiB)、古いものが削除されると、欠落として報告されます。`/diff` は各ターンで変更されたファイルを表示します。

### コンパクション

長いセッションは、モデルのコンテキストウィンドウに収まるようコンパクションされます。コンパクションはセッション JSONL ファイルに要約やプロジェクションのレコードを追記し、元のメッセージはそのままディスクに残します (`/tree` やファイル本体から参照できます)。

```text
/compact                      compact now
/compact keep the migration plan   compact with a focus instruction
```

4 つの圧縮ステージ (`prune`、`offload`、`remote`、`local`)、しきい値の優先順位、失敗時のバックオフや `stalled` 処理、`compact` プラグインの設定は [使用量とコンパクション](usage-and-compaction.md) を参照してください。リクエストごとに毎回送信され圧縮対象にならない要素については [コンテキスト](context.md) を参照してください。

### エクスポートとコピー

- `/export [path]` は会話を秘匿処理した Markdown として非公開権限 (Unix では `0600`) で書き出します。パスを省略すると、作業ディレクトリに `mare-session-<date>-<time>.md` というファイルができます。`/export-md` は別名です。
- `/copy` は最後の応答を Markdown のソースとしてクリップボードにコピーします。コードブロックがある場合は、ピッカーで各ブロックか応答全体を選べます。ピッカーで `w` を押すと選択をファイルに書き出し、`a` を押すと「常に応答全体をコピーする」を記憶します。`/copy 2` は、後ろから 2 番目の応答をコピーします。クリップボードへの経路では、SSH 越しの場合に OSC 52 を使います。

### セッションを削除する

`/delete` は現在のセッションを、添付ファイルとスナップショットごと削除し、新しいセッションを開始します。`/delete <path>` は、確認の後、そのパスにあるセッションファイルを削除します。別のプロセスがそのセッションを開いている間は、削除は拒否されます。ピッカーの `Ctrl+D` は、選択中の行に対して同じことをします。削除の取り消しはできません。
